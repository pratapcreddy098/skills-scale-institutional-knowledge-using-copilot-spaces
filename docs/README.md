# OctoAcme Project Management Docs

Welcome to the OctoAcme Project Management Docs repository. This centralized knowledge hub contains all process documentation, workflows, roles, and guidance needed to execute projects consistently and effectively across the organization.

## Project Management Processes Overview

OctoAcme uses a **lifecycle-based project management approach** that emphasizes customer value, iterative delivery, clear ownership, and data-informed decisions. Our framework is built on psychological safety and continuous improvement, ensuring teams can deliver reliable, maintainable results while reducing single-person dependency risk.

### Core Workflow Stages
Projects progress through five key stages:

1. **Initiation**: Validate business need, align stakeholders, and establish success metrics through a Project One-pager
2. **Planning**: Break work into shippable increments, identify dependencies, and define release timelines
3. **Execution**: Build, test, review, and iterate using daily standups, sprint planning, and a structured project board
4. **Release**: Deploy to production with pre-release requirements, smoke tests, and rollback plans
5. **Retrospective**: Capture learnings and convert them into actionable process improvements

### Core Roles & Personas

OctoAcme defines clear roles to ensure accountability and smooth collaboration:

- **Project Manager (PM)**: Coordinates delivery, manages schedules, risks, and communications
- **Product Manager (PdM)**: Defines outcomes, prioritizes the backlog, and measures success
- **Developers**: Implement features, collaborate on design, maintain code quality
- **QA/Testing**: Validate quality and acceptance criteria
- **Stakeholders**: Provide inputs, approvals, and strategic direction

See [Roles and Personas](octoacme-roles-and-personas.md) for detailed role descriptions and responsibilities.

### Communication & Cadence

Regular, structured communication keeps teams aligned:

- **Weekly sync**: PM + PdM alignment
- **Twice-weekly standups**: Delivery team progress, blockers, dependencies
- **Monthly stakeholder updates**: High-level progress and outcomes
- **Ad-hoc escalations**: For risks and blocking issues

### Quality Assurance Practices

Quality is baked into every stage:

- **Unit & integration tests**: Validate new logic and integrations
- **Automated CI/CD**: Tests, linting, and security scans on every PR
- **Code reviews**: Minimum one approval required before merge
- **End-to-end testing**: Smoke tests for critical flows before release
- **Manual QA**: Feature acceptance validation when needed
- **Risk monitoring**: Weekly risk register reviews and escalation protocols

## Key Principles

- **Customer-first**: Prioritize customer value and usability
- **Iterative delivery**: Deliver small, testable increments frequently
- **Clear ownership**: Every project has a named PM and Product Lead
- **Data-informed decisions**: Measure impact and iterate based on evidence
- **Psychological safety**: Encourage feedback, learning, and continuous improvement
